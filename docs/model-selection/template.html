student-job-match-bench · KIT-254

Reranker Model Selection

How complex should the LambdaMART reranker be, does it need more data, which features carry it, and does a simple linear model do almost as well? Five-fold cross-validation over synthetic student profiles, scored against an LLM judge's grades.

Findings

    Method

    Data. 352 public job postings, 200 synthetic student profiles (seven career tracks, four class years). For each profile the candidate set is the hybrid retriever's top 50 jobs the student is eligible for. Only candidates the judge had already graded are used, so the experiment made no new model calls.

    Labels. Grades 0–4 from an LLM judge (gpt-4.1-mini with code-enforced eligibility rules). On 50 held-out pairs the judge matches a stronger AI grader exactly 62% of the time (quadratic κ 0.66). No human-graded labels are used here yet.

    Model. LightGBM LambdaMART on 17 cheap features: retrieval scores and rank, track and location match, level match, skill and interest overlap, flags for restricted programs and stated rules, and log description length. Baseline orderings use the same candidates.

    Evaluation. 5-fold cross-validation by profile, folds stratified by career track, so a student's pairs are never in both training and test. Metric: NDCG@10 of each profile's judged candidates, reordered by the model. ROC uses out-of-fold scores with "relevant" defined as grade ≥ 3.

    Caveats

    The reranker learns from the same judge that scores it, so these numbers measure how well a cheap model reproduces the judge, not agreement with people. Scoring only judged candidates (a reranking of the judged pool) favours models that sort that pool well and says nothing about jobs no system surfaced. Profiles are synthetic.

    Open questions

    1. Is picking the simplest model within one standard error of the best the right rule here, given the fold-to-fold spread?
    2. Description length looks like a proxy for where a posting came from. Is dropping it, or replacing it with an explicit source feature, the better fix?
    3. Gain-based importance and drop-one ablation disagree on several features. Would grouped or permutation importance give a fairer picture with correlated features?
    4. With labels from an AI judge, how many human-graded pairs would make the test set trustworthy?
